Privacy Policy

Version 2.0 and later

No Collection by the Developer

The developer operates no backend for ArchiveSorter and receives no documents, recognized text, or usage data. No account is required. The app contains no advertising, analytics, or tracking.

Processing on Your Device

Text recognition (OvisOCR2), classification, summaries, and document-based answers (Qwen 3.5 4B) run entirely on your device. Documents, recognized text, and questions never leave the device for this – unless you explicitly connect your own model server (see below).

The on-device models require an iPhone or iPad with at least 6 GB of RAM. Version 2.0 does not use Apple Foundation Models. If a document has more than five pages, the app skips AI reading and classification. You choose its folder yourself. This limit also applies when you use your own model server.

Model Downloads

Only after your explicit action does Apple deliver the immutable model packs OvisOCR2 and Qwen 3.5 4B as Apple-hosted Background Assets. Only model weights, tokenizers, configurations, and license and attribution files are downloaded; no documents or text are transferred. Apple's privacy terms and your carrier's terms apply to the download's network metadata.

Device Library

A device library lives in the folder you choose on this device or on a connected drive. The folder contains the filed documents as PDF, the unchanged originals, and the recognized text. The metadata database (type, folder, issuer, date, amounts, tags, summaries, household assignment), the processing and change journals, deletion markers, and the history of your questions live in this device's private app storage; the folder alone is therefore not a complete backup – use the Backup function in Settings for that; a backup also contains the history of your questions. The app creates backups and exports in the folder you choose for them; if that folder is in a cloud folder, that provider's rules apply; this is not collection by the developer.

Cloud Library (Sync Between Your Devices)

If you choose a folder in iCloud Drive, at another provider integrated through the system, or on a network share, ArchiveSorter creates a cloud library there or joins an existing one. Each device keeps its own private working copy and writes to the chosen folder: change files with the documents' metadata (type, folder, issuer, date, amounts, tags, summaries, household assignment, file name and filing path, trash and deletion state), the originals, the filed PDFs, the recognized text, small preview images of the first page, document texts prepared for “Ask”, the categories, the names of the people in your household, the device name you chose, a copy of the library database, and a lock file with the app identifier and a device identifier. Other devices with access to this folder read and show this data. With a mirror (“Library with mirror”) the app also keeps a readable copy of the filed PDFs in a folder you choose. Transfer and storage are handled by the folder's provider (for example Apple for iCloud Drive) under its terms; the developer receives nothing. The history of your questions is not synced.

Your Own Model Server (Optional)

In Settings you can connect your own server in your local network (LM Studio, Ollama, or an OpenAI-compatible server); only addresses in the local network are accepted. Before activation the app sends only fixed test requests without document data; an optional API key is stored in this device's keychain. Once you confirm the server with “Use these models”, ArchiveSorter sends page images, recognized text, and your questions to this server for processing. What happens to them there is decided by the server's operator; the developer receives nothing.

Local to This Device Only

The private app container keeps settings, the search index, and preview images. Model packs live in Apple's managed, read-only asset storage. For the system search (Spotlight), the type, issuer, date, folder, summary, and tags of filed documents are kept in this device's search index; page text is not stored there.

Deletion

The trash keeps metadata and search state for restoration. Permanent deletion removes the filed copy, the original, the recognized text, and the index entries; a deletion marker remains in private app storage so that a backup of this device does not restore the document unintentionally.

4. Model Downloads and User-Chosen File Providers

4.1 Hugging Face Model Downloads

After you explicitly start the downloads, ArchiveSorter fetches the weights and required supporting files for OvisOCR2 and Qwen3.5 from the Hugging Face Hub (huggingface.co). The app does not add document content or app-usage analytics to those requests. Standard network metadata such as your IP address and HTTP headers is processed to deliver the files. 4.2 File Provider Library Folders

If you select a folder supplied by iCloud Drive, Dropbox, OneDrive, Google Drive, or another File Provider, that provider may upload and synchronize:

  • document files and exact original backups;
  • complete OCR text in plaintext sidecars;
  • temporary Input, processing, and deletion-staging files; and
  • checksum-protected recovery and synchronization records.

Recovery records can contain filenames and relative paths; classification and organization; document dates, types, and kinds; insurance, financial, and recipient fields; tags; review, trash, and processing state; generated summaries, topics, actions, entities, and snippets; hashes, timestamps, and file evidence; immutable revision history; transaction journals; and deletion tombstones. The selected provider’s privacy, retention, Recently Deleted, and file-versioning rules apply. Provider synchronization is separate from Developer collection.

5. Permissions the App Requests

  • Camera — only when you scan a document using the in-app document scanner. Captured images are processed on-device and stored only in the folder you selected as your library.
  • Face ID / Touch ID — only to unlock the app, if you enable App Lock. Biometric data is handled by iOS and never seen by the app or the Developer.
  • File access — the app reads and writes the library folder you explicitly select and files you import or share.

6. Data Storage and Deletion

Device-local data stays inside each device’s private app container. The live SwiftData database, FTS/AgenticSearch database, search chunks and embeddings, thumbnails, conflict copies, and update or recovery database snapshots reside in Application Support; downloaded model artifacts reside in Caches; and preferences/settings reside in UserDefaults/Preferences. A legacy .database folder in a library may remain only as a cold hand-off copy; it is not the live index.

Soft Delete retains metadata and search state for restoration. Permanent Delete removes the app-managed document copy, matching original backup, plaintext OCR sidecar, and local database projection. The app also attempts best-effort cleanup of matching device-local thumbnail cache entries; a cache I/O failure does not weaken the committed removal of core bytes and projection. The recovery manifest, immutable revision history, transaction journals, and deletion tombstone remain in the selected library so another device does not restore the document. A File Provider may retain its own copies under its retention, trash, or versioning rules. Deleting the app removes its local container but does not by itself delete a library held by a File Provider.

7. Children’s Privacy

ArchiveSorter is not directed at children under 13. The Developer does not knowingly collect data from children or any other users. A File Provider you select processes the shared library data described above under its own terms.

8. Third-Party Services

The app does not include any third-party analytics, advertising, crash reporting, or tracking SDKs. Hugging Face is contacted only after you start a model download. A File Provider is involved only when you choose a folder it supplies.

9. Your Rights

Because the Developer does not collect or store any personal data about you, there is no personal data to access, rectify, delete, or port. You retain control of the data in the app, its local containers, and your chosen library or storage provider, subject to that provider’s retention and versioning rules.

Der Papierkorb behält Metadaten und Suchstatus für eine Wiederherstellung. 2. Données collectées par le Développeur

Aucune par le Développeur. ArchiveSorter ne collecte, n’enregistre, ne transmet ni ne stocke aucune donnée personnelle, donnée d’utilisation, donnée analytique, rapport de plantage, identifiant publicitaire ou identifiant d’appareil sur un serveur exploité par le Développeur.

Le Développeur n’exploite aucun service backend pour cette application.

3. Traitement sur l’appareil

OvisOCR2 transcrit les pages complètes des documents. Qwen3.5 4B traite ensuite tout le texte reconnu pour le classement, les résumés, le rangement et les réponses fondées sur les documents. Dans l’app distribuée, l’OCR et l’inférence d’IA s’exécutent sur votre appareil avec des modèles MLX natifs. Apple Foundation Models n’est utilisé localement que lorsque la fonction et le contexte le permettent.

Le Développeur ne reçoit ni vos documents ni les textes reconnus. Le stockage et la synchronisation par un fournisseur de fichiers que vous choisissez sont décrits séparément ci-dessous.

4. Téléchargements de modèles et fournisseurs de fichiers choisis

4.1 Téléchargements de modèles Hugging Face

Après votre lancement explicite des téléchargements, ArchiveSorter récupère depuis Hugging Face Hub (huggingface.co) les poids et fichiers d’accompagnement requis pour OvisOCR2 et Qwen3.5. L’app n’ajoute à ces requêtes ni contenu documentaire ni données d’analyse de l’utilisation. Les métadonnées réseau habituelles, telles que l’adresse IP et les en-têtes HTTP, sont traitées pour fournir les fichiers. Les conditions de confidentialité et de conservation de Hugging Face et des opérateurs réseau s’appliquent à ces métadonnées.

4.2 Dossiers de bibliothèque d’un fournisseur de fichiers

Si vous choisissez un dossier fourni par iCloud Drive, Dropbox, OneDrive, Google Drive ou un autre fournisseur de fichiers, celui-ci peut téléverser et synchroniser :

  • les fichiers de documents et les sauvegardes originales exactes ;
  • le texte OCR complet dans des fichiers annexes en clair ;
  • des fichiers temporaires d’entrée, de traitement et de préparation de suppression ; et
  • des enregistrements de récupération et de synchronisation protégés par somme de contrôle.

Les enregistrements de récupération peuvent contenir des noms de fichiers et chemins relatifs, le classement et l’organisation, les dates, types et genres de documents, des champs d’assurance, financiers et de destinataire, des étiquettes, les états de vérification, corbeille et traitement, des résumés, sujets, actions, entités et extraits générés, des empreintes, horodatages et preuves de fichiers, ainsi que l’historique immuable des révisions, les journaux de transactions et les marqueurs de suppression. Les règles de confidentialité, conservation, éléments récemment supprimés et versions de fichiers du fournisseur choisi s’appliquent. Cette synchronisation n’est pas une collecte par le Développeur.

5. Autorisations demandées par l’application

  • Caméra — uniquement lors de la numérisation d’un document avec le scanner intégré. Les images capturées sont traitées sur l’appareil et stockées uniquement dans le dossier que vous avez sélectionné comme bibliothèque.
  • Face ID / Touch ID — uniquement pour déverrouiller l’application si vous activez le verrouillage. Les données biométriques sont gérées par iOS et ne sont jamais accessibles à l’application ou au Développeur.
  • Accès aux fichiers — l’application lit et écrit le dossier de bibliothèque explicitement sélectionné et les fichiers que vous importez ou partagez.

6. Stockage et suppression

Les données locales restent dans le conteneur privé de l’app sur chaque appareil. La base SwiftData active, la base FTS/AgenticSearch, les segments et embeddings de recherche, les vignettes, les copies de conflits et les instantanés de base pour mise à jour ou récupération résident dans Application Support ; les artefacts de modèles téléchargés résident dans Caches ; les préférences et réglages résident dans UserDefaults/Preferences. Un ancien dossier .database dans une bibliothèque peut subsister uniquement comme copie de transfert à froid ; il ne constitue pas l’index actif.

La suppression réversible conserve les métadonnées et l’état de recherche. La suppression définitive retire la copie du document gérée par l’app, la sauvegarde originale correspondante, le fichier annexe OCR en clair et la projection locale de la base de données. L’app tente aussi, dans la mesure du possible, de nettoyer les entrées correspondantes du cache local de vignettes ; un échec d’E/S du cache ne remet pas en cause la suppression validée des données principales et de la projection. Le manifeste de récupération, l’historique immuable des révisions, les journaux de transactions et le marqueur de suppression restent dans la bibliothèque choisie afin qu’un autre appareil ne restaure pas le document. Un fournisseur de fichiers peut conserver ses propres copies selon ses règles de conservation, corbeille ou versions. La suppression de l’app retire son conteneur local, mais pas automatiquement une bibliothèque détenue par un fournisseur.

7. Protection des mineurs

ArchiveSorter ne s’adresse pas aux enfants de moins de 13 ans. Le Développeur ne collecte sciemment aucune donnée d’enfants ni d’autres utilisateurs. Un fournisseur de fichiers choisi traite les données partagées de la bibliothèque décrites ci-dessus selon ses propres conditions.

8. Services tiers

L’application n’intègre aucun SDK d’analyse, de publicité, de rapport de plantage ou de suivi tiers. Hugging Face n’est contacté qu’après le lancement d’un téléchargement. Un fournisseur de fichiers n’intervient que lorsque vous choisissez l’un de ses dossiers.
